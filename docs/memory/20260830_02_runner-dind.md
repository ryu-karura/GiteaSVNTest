# 20260830_02 Gitea Actions runner を DinD 化して rootless podman でジョブ完走

前日の未解決 B（rootless podman で Actions ジョブが完走しない）を解消。

## 試したイメージと結果

| イメージ | 構成 | 結果 |
|---|---|---|
| `gitea/runner:3.3.1` | ホストの docker.sock をマウント | ジョブ受信まで OK、実行コンテナ起動でソケットの uid/権限不一致 → 完走せず（`Creating 1 workers for 0 executors` ループ） |
| `gitea/runner:3.3.1-dind-rootless` | コンテナ内で rootless dockerd | 起動失敗。`[rootlesskit:parent] error: failed to setup UID/GID map: newuidmap ... Operation not permitted`（rootless podman の中で userns を入れ子にできない） |
| **`gitea/runner:3.3.1-dind`** | コンテナ内で root の dockerd（`privileged: true`） | **ジョブ完走**。userns の入れ子が無いので rootless podman 上でも動く |

## compose の変更（infra/docker-compose.yml）

- `image: gitea/runner:3.3.1` → `gitea/runner:3.3.1-dind`
- `privileged: true` を追加
- `- ${DOCKER_SOCK:-/var/run/docker.sock}:/var/run/docker.sock` のマウントを削除
- `gitea-runner-data:/data`（登録情報の永続化）は維持 → 再作成時に登録トークン不要

再作成: `docker compose up -d --force-recreate gitea-runner`
（既存の `/data` に登録が残っているため `declare successfully` で即再登録）

## 検証

- `.gitea/workflows/ci.yml`（`echo` / `uname -a` / `docker version` の 3 ステップ）を
  contents API で更新して push → task 3 として runner が受信
- コンテナ内 dockerd 稼働（`Docker daemon ... version=29.7.2`、`API listen on /var/run/docker.sock`）
- `podman exec gst-gitea-runner docker run --rm alpine echo` も成功（イメージ pull + ネットワーク OK）
- 結果: `state: success`、5 ステップ（Set up job / echo / uname / docker version / Complete job）
  すべて success、約 1m4s

## E（ワークフロー結果の取得手順）も確定

Gitea 1.22 に Actions の REST API は無い（`/api/v1/repos/.../actions/runs` は 404）。
結果は次で取得:

- runner ログ: `podman logs gst-gitea-runner`
- 管理画面: `http://localhost:3000/testorg/sample-app/actions`
- 内部 JSON（要セッション cookie + `x-csrf-token`）:
  `POST /{owner}/{repo}/actions/runs/{RUN}/jobs/{jobIndex}` → `{state, jobs[].steps[].status, job0.status}`
  `state == "success"` で成功。

MANUAL.md 手順 2-4 に上記を反映。README.md / infra/README.md / infra/.env.example も
「runner は DinD 版、ホスト socket 不要」に更新。

## 補足

- `NewParallelExecutor: Creating 1 workers for 1 executors`（前日は `0 executors`）が
  進捗のサイン。その後ログが止まって見えるが、内部 dockerd 側で短命コンテナ
  （ネットワーク確認・イメージ展開）が作られては消えるだけで、ジョブ自体は進んでいる。
- DinD の起動ログに `mount: permission denied (/sys/kernel/security)`、
  `No cpu cfs quota support`、nftables のルール削除エラーが出るが、ジョブ完走には影響なし。
- `git-apache` は前日削除済み。cockpit の実操作確認（D）と GitHub PR 手順 E2E（C）は未着手。
