# 20260829_07 実コンテナ検証

環境: WSL2 上の podman 5.8.2（rootless）+ podman-compose 1.5.0。`docker` は podman エミュレーション。

## 対応した差異

- **short-name 解決**: podman が `enforcing` で TTY なしだと `httpd` 等の解決に失敗。
  `~/.config/containers/registries.conf` に `unqualified-search-registries=["docker.io"]` /
  `short-name-mode="permissive"` を追加（ユーザー環境設定。リポジトリ非依存）。
- **profiles 未対応**: podman-compose が `profiles: ["seed"]` のサービスで
  `missing services [seed]` エラー。seed は `docker build` で個別ビルドして対応。
- **cockpit / gitea-runner**: `/var/run/docker.sock` 依存のため検証対象から除外。

## 発見・修正した不具合（コミット対象）

- **healthcheck の curl 不在**: `httpd:2.4-bookworm` と `redmine:6.1.2` イメージに `curl` が無く、
  全 healthcheck が `curl: not found` で失敗（サービス自体は正常稼働）。
  - `infra/svn-apache/Dockerfile` / `infra/git-apache/Dockerfile`: `curl` を追加インストール。
  - `infra/docker-compose.yml`: redmine / gitea の healthcheck を `wget -q -O /dev/null` に変更
    （両イメージに wget は存在）。svn1 / svn2 は `curl -sfL`（301 リダイレクト対応）に。

## 追加で判明・修正した不具合（コミット対象）

- **Gitea 管理者が未作成**: `gitea/gitea` イメージは管理者を自動作成しない。
  - `docker-compose.yml`: `GITEA__security__INSTALL_LOCK: "true"` を追加。
  - 手順: `docker compose exec -u git gitea gitea admin user create --admin ...`（root 実行は拒否）。
  - `infra/README.md` に手順1として追記。
- **docker exec が SECRET_KEY_BASE 未継承**: entrypoint を通らないため
  `bin/rails runner` が production で `Missing secret_key_base`。
  bootstrap 実行時に `-e SECRET_KEY_BASE=...` を明示。README 修正。
- **Redmine デフォルトデータ未投入**: トラッカー / ステータス / 優先度が空 → 課題作成が 422。
  `redmine_bootstrap.rb` に `Redmine::DefaultData::Loader.load('en')` を追加。
- **Redmine API キーは固定不可**: Token モデルが値を自前生成。
  `redmine_bootstrap.rb` は `admin.api_key` を「出力」する方式へ変更。
  `.env.example` / `infra/README.md` / 環境変数対応表を「生成値を控えて使う」に修正。
- **seed の Redmine 課題作成に tracker_id 必須**: `seed.sh` を
  トラッカー ID 動的取得 → プロジェクトに `tracker_ids` + `issue_tracking` を PUT（冪等）→
  課題に `tracker_id` 付与、へ修正。
- **svn2 は svn1 と別イメージタグ**: compose の `build:` 共有でも
  `giteasvntest_svn1` / `giteasvntest_svn2` に分かれる。両方ビルドが必要（検証手順の注意）。
